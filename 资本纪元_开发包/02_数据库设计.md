# 资本纪元：交易所大亨

## 02. 数据库设计

本文档目标：

- 给出首版 PostgreSQL 数据库设计
- 明确核心表、关系和索引
- 支持 Rust 服务端直接开始建模

说明：

- 本版以 MVP 为目标
- 优先保证账户、股票、IPO、订单、新闻、信用链路
- 银行先保留基础字段，复杂经营可在第二阶段增强

---

## 一、数据库分域

建议按以下业务域组织表：

1. 用户与鉴权
2. 钱包与资产
3. 股票与IPO
4. 订单与成交
5. 银行与贷款
6. 新闻与公告
7. 信用与风控

## 三、核心关系图思路

主关系如下：

- 一个 `users` 对应一个 `wallets`
- 一个 `users` 对应一个 `credit_profiles`
- 一个 `stock_entities` 可对应一个 `stocks`
- 一个 `ipo_issues` 对应多个 `ipo_subscriptions`
- 一个 `stocks` 对应多个 `stock_orders`
- 一个 `stocks` 对应多个 `stock_trades`
- 一个 `banks` 对应多个 `loan_accounts`

## 五、索引建议

以下索引应优先创建。

## 5.1 用户与资产

- `users(username)` 唯一索引
- `wallets(user_id)` 唯一索引
- `portfolio_positions(user_id, stock_id)` 唯一索引

## 5.2 股票与交易

- `stocks(stock_code)` 唯一索引
- `stock_orders(stock_id, order_status, created_at)`
- `stock_trades(stock_id, created_at)`
- `ipo_subscriptions(ipo_id, user_id)`

## 5.3 银行与贷款

- `banks(founder_user_id)`
- `loan_accounts(bank_id, loan_status)`
- `loan_accounts(user_id, loan_status)`

## 5.4 新闻与信用

- `news_items(published_at desc)`
- `announcements(issuer_type, issuer_id, published_at desc)`
- `credit_events(user_id, created_at desc)`

## 六、金额与数值规范

所有金额建议：

- 使用 `numeric(20,4)`

原因：

- 防止浮点误差
- 兼顾较大金额和小数计算

股数建议：

- 使用 `numeric(20,4)` 或 `bigint`

如果你明确不允许碎股，可统一使用 `bigint`。

---

## 七、状态字段建议

状态建议统一使用短枚举字符串，便于 Rust 映射。

例如：

- `stock_status`: `pre_ipo` / `subscribing` / `listed` / `halted` / `delisted`
- `ipo_status`: `draft` / `reviewing` / `approved` / `subscribing` / `allocating` / `listed` / `rejected`
- `loan_status`: `active` / `overdue` / `repaid` / `defaulted`
- `bank_status`: `active` / `warning` / `run_risk` / `taken_over`

---

## 八、事务边界建议

以下操作必须在数据库事务中完成：

1. 下单冻结资金
2. 撮合成交与持仓更新
3. IPO申购冻结资金
4. IPO配售与退款
5. 贷款发放与钱包入账
6. 还款扣款与信用更新
